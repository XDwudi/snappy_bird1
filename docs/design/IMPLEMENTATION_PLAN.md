## 第一批可执行任务（仍待开发指令）

1. TASK-006 固定步长、输入记录、seed回放；先替换工程启动页循环的游戏用法，保留回归。
2. TASK-007 飞行、障碍安全模板、碰撞与生命；前置006，关卡体感真机验证。
3. TASK-008 三种基础武器与M01–03；前置007，输出来源和实体上限可观察。
4. TASK-009 升级候选与15技能；前置008，前置检查/重抽/冻结恢复不改变物理时间。
5. TASK-010 B01、结算和完整4分钟流程；前置009，完成原型试玩。
6. TASK-011 原型复盘，批准/修订后进入MVP；记录是否保留5血、自动攻击与三个初期流派。

任务卡需各自明确负责文件、验收与依赖。当前不拆给多个agent同时实现，公共技能契约先冻结再考虑协作。

## 微信测试/上传安排

已获用户授权调用已安装的微信开发者工具测试与上传。服务端口与登录状态已检查通过。
目前工程仅游客AppID，打开项目返回“AppID不存在”；真实AppID是必要接入信息，不是再次请求操作授权。
拿到AppID后配置明确基础库，重新构建，打开并验证启动底座；上传版本描述必须标注“工程验证/无玩法”。
后续上传P1/P2候选也沿用授权，记录commit、基础库、上传版本和CLI结果。
上传开发版本不等于提交审核/正式公开发布；正式发布按用户届时指令和平台流程执行。

## 本次设计的五项关键选择

- 保留Flappy式拍翅，战斗自动执行。
- 基础5血，撞击恢复，增强几分钟以上的可玩性。
- 首先平衡12分钟模式，再推出6/24分钟模式。
- 长期六流派66技能，原型15、MVP35，逐步验证有趣程度。
- Boss以生存通关为底线，以击破获得额外成绩，让防御构筑有合理出口。

这些是策划确认重点，不要求用户逐条审每个初始百分比。具体调参通过版本化实验迭代。
