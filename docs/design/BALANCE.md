# 成长与平衡设计

> 版本提示：本文件为原始 v0.2 长期设计。用户已要求开始开发；首版范围、章节规则与取舍以 [章节扩充](CHAPTER_EXPANSION.md) 和 [ADR-003](../adr/003-first-playable.md) 为准，原15技能/4分钟安排已被替代。
> 本文件给出**待验证的假设、上限和实验方法**，不是已经达成平衡的报告。
> 首轮以标准12分钟、普通难度、无局外属性加成为唯一基准；其他模式单独调参。

## 1. 初始数值与比较单位

| 参数             | 初值                                                              |
| ---------------- | ----------------------------------------------------------------- |
| 最大生命         | 基础5，全局最多8                                                  |
| 临时护盾         | 全局最多3点，普通伤害先扣盾；同一次重击剩余伤害再扣生命           |
| 受伤无敌         | 1.2s；首次发生伤害开始计时，不通过随后同帧碰撞延长                |
| 自动攻击增速     | 合计最多+60%；间隔 = 基础间隔 / (1 + 增速)                        |
| 同类增伤         | 加法，普通同桶加成上限+100%；不同机制乘区最多“伤害×易伤×主副效率” |
| 易伤             | 同类取最大，最多20%；多名伙伴不重复挂同名易伤                     |
| 怪物减速         | 普通最多50%；Boss最多10%且受控制占比约束                          |
| 护盾获能         | 单来源最多每3s成功生成1次；更长的技能冷却优先                     |
| 回复             | 每段所有战斗内技能合计最多2血；驿站另结算；满血不会储存待回复量   |
| 碰撞无敌占比目标 | 完整构筑常规玩法≤25%，仅用于平衡审查，不隐藏修改技能说明          |
| 主/副武器效率    | 1.0 / 0.6；作用于其直接与派生伤害，不能再次叠乘到同一份伤害       |

盾不会阻止“受到伤害”事件，但完全挡住伤害时不产生“生命损失”。所有技能采用图鉴明确的事件口径。
同名Buff只按该ID刷新/叠层，不因为事件多次投递生成多个独立实例。
技能写“爆炸6伤”属于自己的基础伤害，默认吃来源伤害桶与主副效率；写“40%直接伤害”直接引用结算前伤害快照，
只追加目标易伤，不再次吃同一桶增伤。无伤害来源的防御事件派生伤害以关联武器为归属。

## 2. 经验保底和升级节奏

基础经验每有效游玩秒1点，菜单、暂停和后台停止。普通穿门给可见反馈但不额外再计算一份保底经验。
杀敌、精准穿门、风险路线给额外经验；所有额外经验累计不得超过当时基础经验的15%。
勤学增加的是该额外来源，最终仍受15%封顶。这样输出低的防御构筑不会因少杀怪而永远落后等级。

标准模式18次升级的**累计经验阈值**：

```text
20, 50, 80, 115, 150, 195, 240, 285, 325,
365, 405, 445, 485, 525, 565, 605, 635, 660
```

例：没有击杀加速的玩家在20s得到第一次，150s得到第5次；如果累计有15%额外经验，第5次最早约130.5s。
Boss期间产生的升级排入队列，在脱离或安全修整时展示；如果尚未消耗的升级超过1次，连续选卡，世界保持冻结。
最后1分钟不新增基础等级；到满级后的经验转结算分，不能再次发技能升级。试炼只提前发放下一次升级。

短途12次阈值：15, 35, 60, 85, 110, 140, 175, 205, 235, 265, 290, 315。
远征24次阈值：前18次与标准相同，额外为780, 900, 1020, 1140, 1260, 1380；
后半程成长变缓，因此用新攻击组合而非无限敌血扩充挑战。玩家生命耗尽会提前结束，不保证拿满等级。

## 3. 抽卡规则（可实现规格）

1. 先过滤合法候选：已启用内容、前置满足、未满级、未放逐、槽位可用；进化须还未进化。
2. 三个逻辑篮子：A已有武器/已投资流派的成长，B非重复的跨路线或共鸣，C防御/通用。
3. 每篮取1个，按ID去重；稀缺时从全合法池补。不是对未满足前置的卡临时解除限制。
4. 候选基础权重：已有技能升级4、同派新机制3、其他派新机制1、通用2；精通/进化/共鸣默认1。
5. 如果两次选择中均未出现主武器升级且未满级，下次A槽强制提供主武器升级；玩家可以不选。
6. 进化达标后最多两次安全选卡内出现；满足共鸣前置同样最多两次机会，但进化占优先槽。
7. 重抽不推进保底计数，不重复刚才的三项（池不足时允许部分重复并提示）；每局2次。
8. 放逐必须选中一项、只影响未来候选，不能撤销已有技能；不可把所有可用基础输出都放逐后仍保底出进化。
9. 兜底：缺血→回1血；盾不足→补1点临时盾；其他→结算币。兜底是即时资源，不占技能位。
10. 同seed、同选择、同内容版本，候选必须一致。表现层随机数不得改变抽卡随机流。

初始武器一级免费；进化的最短投入例：E01再升2次+E02升2次+E03升1次→本派等级和6，
再选E07、E08，共7次升级形成进化。仅凑前置也可成型，但没有额外多派收益。
跨派组合有前置和槽位成本，不把“凑标签”设计成获得独立整套武器价值的捷径。

## 4. 输出与生存预算

一级单体木桩、无支援时基础武器理论DPS约8.8–9.5；三级约15.5–17。
例如火羽一级：6/0.8 + 4/2 = 9.5（灼烧持续覆盖时）；铁翼三级：17/1 = 17。
链条、贯穿、控制、治疗和追踪的价值另计，不能仅凭单体木桩判断强弱。

有效伤害 = 攻击频率 × 单次期望伤害 × 命中率 × 可攻击时间占比。
进化提升目标是同等额外一次投入的局部效能约20–35%，不是未经代价的两倍伤害。
共鸣目标为当前构筑总有效输出/生存收益约10–18%；超过25%需优先检查递归和乘区。
防御派允许击破速度低10–20%，通过较少受伤弥补；不能以通关率低20个百分点作为所谓风格差异。

Boss调参例：完整输出构筑若有效DPS（含命中、空窗）为12/21/30，45s内总量为540/945/1350。
对360/640/900生命，约30s击破，给操作波动留余量。该DPS是目标假设，需真实原型测量后调HP。
防御构筑无法击破时仍可生存通关，但其正常操作通关率不能依靠这条规则掩盖不合理的输出弱势。

## 5. 单组合防漏洞规则

- 净空→冰环→清弹不能闭环，冰环不清弹；连锁不得重复回到同一敌人。
- 护盾击破→电荷→增伤不产生护盾；只有明确冷却到期或独立事件能补盾。
- 灼烧刷新不立即追加首跳；DOT死亡和冻结死亡只有一个对应事件ID。
- 多枚子弹同帧伤害可叠加到敌人，但有全局触发冷却的技能只触发一次。
- 每根事件因果链最多2代派生；技能文本可再收紧，不能越过此规则；第3代纯表现也不再生伤害。一条连锁的多次跳跃属于同一代，用已命中集合防回跳，不逐跳增加代数。
- 死亡事件只出一次；“击败敌人”不是“造成任何伤害”；召唤物退出屏幕不算被击败。
- 退出/继续游戏不能重置段落治疗、一次性屏障或试炼奖励；恢复采用保存的剩余冷却。
- 暂停、升级保护、地形推离不可计为闪避、受击或精准门收益；Boss门框可以提供真实穿门事件。

## 6. 验证矩阵与通过目标

### 设计静态检查（本轮可做）

唯一ID、每派8条、级数、前置引用、共鸣数量、首版范围计数与单局升级预算。
这些检查只说明策划一致，不证明效果代码正确、抽卡分布正常或游戏好玩。

### 原型之后的确定性模拟

- 固定100个seed；6纯派+9命名共鸣，各跑保守/普通/精准三种输入策略；至少4500局组合。
- 对每一策略使用同seed做成对比较，记录通过/死亡时间、受伤、输出来源、候选拒绝与成型时间。
- 单独模拟至少10000局抽卡，测前置死锁、无合法候选频率、进化出现率；不将机器人选择率当真实玩家偏好。
- 可达性搜索覆盖起始y/vy和天气组合；回放复现失败单独报错。

### 人类试玩（真正的平衡判断）

- 首轮≥6人，每人3局；检查操作负担、选卡理解、死因可解释性，先修“玩不懂/必撞”。
- 内容稳定后每派争取≥30局匹配熟练度试玩；记录样本数与95%置信区间，避免把小样本波动说成平衡。
- 目标：同熟练度六纯派通关率差距≤10个百分点；超过该值触发排查，不是小样本一超就立即砍数值。
- 平均成型时间约6–8分钟；大多数普通策略能在第8分钟前见到可用进化（目标≥85%，最终由抽卡模拟验证）。
- 进入第二段的局里，前一分钟死亡率不高于第一段末分钟两倍，检查章节难度断崖。
- 调查“上一局想继续试另一套”的比例；构筑多样性不能只看66个技能数量。
- 测6/12/24分钟的手指疲劳与选卡阅读时间；12分钟多数试玩者出现明显疲劳时先缩短航程/增加安全休息，不急着做24分钟模式。

## 7. 调参顺序与记录

操作手感 → 可达性/读图 → 升级节奏 → 基础武器 → 机制分支 → 进化 → 共鸣 → 怪物/天气组合 → 长短模式。
每轮只改一个类别，记录内容版本、假设、输入seed、改前后结果、已知副作用。
在可玩原型出现之前不写“已经足够平衡”；在真机出现之前不写“性能达标”。
