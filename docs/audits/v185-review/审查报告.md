## 已确认问题

### A01 P1 穿盾柱在顶部存在不可见伤害区

定位：`game/art/Entities.js:98–99`；对应判定 `game/entities/BossHazard.js:43–46`，招式来源 `BossPatterns.js` 的 `rail_switch` 和 `vent_burst`。

柱形攻击绘制从y=130开始，但碰撞没有该下限。玩家可以飞到y=80；第六章磁轨预警结束后，这里没有柱体像素，仍满足穿盾碰撞。实际Canvas检查得到像素alpha=0，同时HP从2降到1、普通盾仍为1。第五章阀口喷发共用同一分支。普通移动墙的上半部预警也从130开始，生效后却从0绘制，存在类似预警范围缺失。

这违背1.8.2的明确预警、1.8.4 UI修复不改变可飞边界，以及1.8.5危险纹理对应实际危险的约定。应让绘制、预警与碰撞共用完整几何范围，利用前景层级保证可见，不应仅为了绕HUD省略真实危险区域。

证据：复现A01；`invisible-column.png`为单独绘制危险物的诊断图，红方块标出y=80碰撞位置，不是微信实机截图。

### A02 P1 无尽后期胜利演出会失去保护并在领奖前死亡

定位：`game/core/Game.js:659–663`、`1367–1372`；`game/systems/EndlessScaling.js:24`。

胜利设置32帧无敌来覆盖30帧演出，但每帧无尽规则又把这段保护压到普通受击无敌上限。15分钟时上限12帧。复现以1HP、离地65px、竖直速度0击败Boss，不再输入；真实Game.update第16帧坠地死亡，胜利演出仍剩14帧，通关记录已经存在，200分奖励却尚未到账。

这不是玩家在正常战斗中被压缩后的合理死亡，而是已经宣布胜利后的结算保护失效。击杀和生存通关共用此入口。应区分战斗无敌与结算保护，后者须覆盖整个演出及奖励交接。无尽难度压缩继续作用于正常战斗技能。

证据：复现A02，`state=gameover, clears=1, score=0`。

### A03 P2 召唤物触发战败后继续遍历空数组并抛异常

定位：`game/core/Game.js:1182–1197`，清场入口 `1332–1348`。

场上至少两只召唤物、玩家1HP、无有效防护时，索引较大的召唤物撞出剧情战败。`_onBossDefeat()`直接把`this.monsters`替换成空数组，却返回false；原循环继续读取下一索引，随后访问不存在对象的`frostFrames`。

复现得到 `TypeError: Cannot read properties of undefined (reading 'frostFrames')`。主循环会捕获异常并继续调度后续帧，所以不是永久卡死或已证实的P0，但本帧更新和渲染被中断。应在碰撞导致数组替换、战斗退出或复活时停止旧循环，或采用与弹幕循环相同的快照及失效检查。

证据：复现A03；报错时已经是 `bossActive=false, monsters=0`。

### A04 P2 无尽仍会抽到已无后续事件的章节之主

定位：`game/config/CampaignAbilities.js:7`、`game/abilities/AbilityRegistry.js:106–111`、`game/systems/AbilitySystem.js:143–157`。

章节之主第六章才解锁。若通过第六章普通升级获得，打开该面板时本章首面板标记已经消耗；此后没有第七章，首面板史诗保底不再有机会触发。进入无尽后既没有章节祝福，也不重置首面板标记，但此卡仍可新抽到，其两个主动承诺都不能兑现，只剩凑派系数量的通用作用。

需区分一个例外：若第六章此前从未打开普通升级面板，先从末章Boss特殊奖励卡取得章节之主，再打开奖励经验升级面板，保底仍可能执行；因此不能笼统声称所有获取方式都不可能触发。真正确定的漏项是无尽卡池未排除它，以及普通获取后核心效果没有后续机会。

1.8.4已经对旅者/章节回响执行了“无后续事件不进池”的原则，章节之主也应按真实事件生命周期筛选。若要保留其原史诗保底定位，需要提前开放或修改保底触发点，再同步策划。

证据：复现A04；前五章不能获得，普通获取后及无尽首面板标记均false，候选资格仍true。

### A05 P2 百分比得分加成在一级时完全被取整吞掉

定位：`game/systems/AbilitySystem.js:355–359`；实际过管计分 `game/core/Game.js:1936–1942`。

得分倍率提前整数化，血契还会再取整一次。没有其他得分增益时，血契一级的+30%、1HP狂暴一级的+25%、天气中风暴之子一级的+20%，实际倍率全部为1；过多少根管道都无法积累出收益。狂暴/风暴的攻速和血契的经验等其他效果仍然有效，不是整张卡失效。

1.8.2明确保留得分增益，现行卡面仍承诺这些百分比。应保留小数倍率并用累计小数或等价方式结算整数显示分数；只删除getStats中的取整，而仍对每次1分单独取整，依然不能兑现小比例收益。还应明确卡面“得分”是否仅指过管分，现代码其他奖分没有使用这个倍率。

证据：复现A05；三个实际倍率均为1。

### A07 P2 停雨残水的交互和Boss冻结行为不一致

定位：`game/systems/WeatherSystem.js:90–96`、`279–282`；提示 `game/art/Effects.js:95`。

停雨后HUD仍提示“残水50%·拍翅甩水”，但onFlap只向activeEffects中的雨转发事件，残水对象不会收到拍翅，水量仍50%。同时进入Boss冻结分支后直接return，残水的重力修饰不再写入；同一份49.5%残水，开战前重力加成为0.2475，战中变0，解冻后又恢复。

这两条路径属于同一未完整接入的残水状态。按1.8.5保留残水/甩水反馈、Boss冻结只停时间的约定，应向残水转发甩水，并在冻结时保留应有的属性效果。若策划希望Boss期间豁免残水重量，则需要正式声明规则并同步HUD，而不能让它显示普通残水状态。

证据：复现A07a、A07b。

### A08 P2 导弹连续碰撞会越过前排而伤害后排

定位：`game/core/Game.js:1787–1802`，对比新武器 `game/systems/CombatSystem.js:88–91` 的命中时间排序。

1.8.5为导弹接入了连续路径命中，但候选仍按怪物数组反向遍历，找到一个布尔命中就结束，没有比较首次接触时间。同一帧路径与两只移动怪物相交时，后添加的远怪可以先扣血，真正先接触的近怪完全无伤。

复现使用实际导弹最高17.5px位移和两只均左移15px的怪物，帧首均未重叠。近、远首次接触时间分别0.369和0.831，结算后却是近怪20HP不变、远怪20→19。应在既定可命中对象范围内按接触时间选目标，明确Boss/机关优先锁定与物理命中次序是两件事。

证据：复现A08。现有弹丸测试的“最近目标”断言只覆盖新武器，未覆盖导弹分支。

### A09 P2 屠龙者的Boss战受击无敌加成漏掉冰雹

定位：`game/weather/HailEffect.js:176–181`，对比 `game/core/Game.js:2296–2302`。

屠龙者卡面承诺“Boss战受击无敌+0.5秒/级”。普通碰撞链会加上此数值，但Boss战仍在运行的冰雹使用独立受击链，只调用基础getInvincibleFrames。两级屠龙者、同一Boss战、同样扣1HP，普通敌弹给予120帧无敌，冰雹仅60帧。

应将Boss战受击无敌计算放到共享函数，让冰雹与普通伤害都接入；如果确实限定伤害来源，应改清楚卡面并纳入策划。普通盾和冰晶转盾各自的特殊规则可保留。

证据：复现A09。

### A10 P2 超载转临时生命被冷却阻挡时提示原因错误

定位：`game/core/Game.js:2120–2125`。

普通盾满层、超载神盾三级、临时生命未满时，护盾补给仍是有效资源。但无尽共享恢复CD未结束时，转换会被拒绝；提示分支只检查普通盾是否未满，因此显示“护盾已满”，而不是“补给冷却中”。

此时实际结果是临时生命未增加，原因是冷却而非容量。1.8.5专门承诺按实际状态区分满盾、冷却和转换，应按普通盾与临时生命的联合容量，以及恢复拒绝原因来选择文案。

证据：复现A10，临时生命0、普通盾满、CD100帧，显示“护盾已满”。

## 待明确的触发规则

A06 生机收割：一级第7次击杀达标时，若治疗自身冷却或无尽共享恢复CD未就绪，计数会保留；冷却结束后却不自动兑现，必须再杀一只才重试。实测达标计数7、恢复CD已到0、HP仍1。卡面同时写了击杀门槛和治疗冷却，没有明确承诺“冷却结束自动恢复”，因此本轮将其列为规则歧义，不计入确认缺陷。建议确定“达标后挂起治疗”或“冷却就绪后的下一次击杀才恢复”，并让文案、提示、测试使用同一规则。
