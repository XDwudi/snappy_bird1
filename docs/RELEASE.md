# 发布流程

工程构建默认只生成候选包。用户已授权调用本机微信开发者工具测试与上传开发版本，可在候选就绪后执行。
工具已连通并登录；真实小游戏AppID/目标基础库与平台验收尚未完成。提交审核和正式发布另按用户指令。

## 候选版准备

- [ ] 产品范围完成，阻断缺陷清零，版本和 CHANGELOG 对齐。
- [ ] main 的目标提交已验证；有远端时 CI 成功，工作区干净。
- [ ] `npm ci`、`npm run verify` 通过；真实 AppID 与已验证基础库配置完成。
- [ ] `npm run build:release` 通过（包含产物检查和模拟环境冒烟）。
- [ ] `dist/build-info.json` 的 mode 为 release，commit 为目标提交，dirty 为 false。
- [ ] 记录产物 SHA256 与包体大小；归档整个候选包和真机验证记录。
- [ ] 在微信工具和双端真机验证**该候选包**；所有 UI、输入、前后台、性能项目完成。

`build:release` 检查配置和打包质量，但无法证明 AppID 属于你、账号有发布权限、工作区已验收或真机兼容。
不能拿冒烟通过替代以上清单。上传前别再次运行会覆盖 dist 的开发构建。

## 微信侧发布

1. 在公众平台核对账号资料、类目、权限以及当前要求的上线材料；按实际功能填写隐私说明。
2. 确认素材/字体/音频授权，AppSecret/私钥未进入运行包。
3. 在开发者工具导入候选 dist，确认 AppID、基础库与上传版本，上传为开发版本。
4. 设置体验版并按测试记录回归；发现问题重新构建、重新记录，不覆盖既有候选证据。
5. 按用户已授权的范围提交审核；记录平台版本、提交、时间和结果。
6. 审核通过后，按产品安排执行发布并验证线上冷启动和核心循环。

已提供的GitHub远端可同步；微信测试和开发版本上传已获授权。上传不等于已获正式公开发布授权。
官方材料与限制以 [微信小游戏文档](https://developers.weixin.qq.com/minigame/dev/guide/) 和当前账号后台为准。

## 发布记录与回退

每个版本记录：Git tag/SHA、npm 版本、基础库、候选包哈希、设备矩阵、上传/审核/发布状态、操作人。
失败时先停止继续发布，保留报错和候选包。线上回退通过微信后台支持的版本操作进行；
不支持直接回退的情况，使用已验证旧提交构建修复候选并重新走平台流程。
Git revert 本身不会影响线上包；有存档或服务端数据时须先判断兼容性。
