# ADR-002：Flappy Roguelike 的确定性与数据驱动

- 日期：2026-09-18
- 状态：提案，策划确认后实施
- 背景：用户明确Flappy基础+Roguelike，短至几分钟、长至半小时，以技能构筑为核心。

## 决策提案

维持TypeScript/Canvas 2D与现有平台隔离；游戏逻辑固定60Hz，表现独立。
玩法用纯领域模块组合，暂不引入通用ECS；内容使用稳定ID、schema和受限效果操作。
世界、抽卡、战斗与纯表现使用独立随机流，统一伤害顺序、因果深度、存档与回放口径。
Boss仍提供穿门事件，确保以飞行技巧触发的流派不会在Boss场景失去核心机制。

## 取舍

单指飞行配自动攻击，避免双操作同时占用同一触摸；技能和站位承担战术选择。
基础5血提高长期一局的容错，但需要撞击后推离、短暂无敌和反刷收益规则。
六派完整内容先写规范，开发按15→35→66条目扩展，避免在基本手感未知时同时实现大量机制。
所有复杂技能仍有代码处理器；数据驱动不等于把任意逻辑表达式放进配置执行。

## 重新评估条件

原型证明单指操作与读弹冲突、实体预算不能满足视觉需求、引擎编辑工具成为资产生产瓶颈，
或三种起始流派无法带来可区分的体验。此时先修改策划，不盲目扩充技能数量。
