# 工程计划与里程碑

当前已实现 v0.2.0 两章首轮试玩版，下一关口是用户试玩和微信真机验收。以下早期里程碑作为历史规划，状态以任务看板为准。
当前39技能/两章范围以 [章节扩充](design/CHAPTER_EXPANSION.md) 为准。单人/agent 协作建议同时在做的任务不超过 1 个。
优先级：P0 阻断下一阶段；P1 核心体验；P2 优化。任务状态以 [看板](tasks/BOARD.md) 为准。

## 正式玩法开发的 Ready 条件

- 明确“微信小游戏”还是“普通小程序页面”，决定是否维持 ADR-001。
- 确认策划提案中的自动攻击、5血、Boss生存通关、12分钟主模式和原型15技能范围。
- 确认渲染路线适合玩法复杂度，明确目标设备和最低基础库。
- 真实小游戏账号/AppID 可供开发者工具和真机预览；至少完成启动验证。
- 第一项玩法任务已经拆成能单独验收的切片。

工程前置可继续离线推进；具体玩法可先做纯逻辑原型，但平台兼容不能标记完成。

## 内部质量目标（不是平台官方限制）

- 总包内部预算初始 2 MiB（排除开发 source map，保守计入构建元信息），配置在 `config/budgets.json`。
- 目标 60 FPS；性能任务应记录真机连续 5 分钟的帧时分布、内存趋势和测试场景。
- 首次可交互目标 3 秒以内，需注明设备、网络、冷启动/热启动；M1 后按实测调整。
- 重开、切后台、来电/音频中断和低端设备是回归必测方向。

## 风险登记

| 风险                               | 应对                                       | 负责人角色 |
| ---------------------------------- | ------------------------------------------ | ---------- |
| 用户实际需要普通小程序             | M1 首先确认平台，玩法继续维持纯逻辑边界    | 产品/架构  |
| 玩法复杂度超过原生 Canvas 适用范围 | 在重资源投入前评审引擎选择                 | 架构       |
| 开发者工具正常，真机异常           | 双端验证、固定基础库、保留证据             | 测试       |
| agent 偏离需求或同时改公共文件     | 小任务、验收卡、文件归属、集成复核         | 任务负责人 |
| 后期包体或性能超预算               | 逐步记录素材、自动包体门禁、阶段性真机基线 | 实现/测试  |
| 账号或上线材料不完整               | M1 确认后台要求，M4 按发布清单复核         | 产品/发布  |
